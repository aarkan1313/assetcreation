## Key decisions during build

### Option C — per-slot tier+layer addressing (5a)
The plan originally had `splat_layer_indices: ivec4` + a slot uniform
mapping a single channel to a single (tier, layer). Forest's mixed-
tier slots broke that — `scrub_dense` + `rocky_slope` are hero 4096²,
`tundra_lichen` is standard 1024². The fix: 3 ivec4 uniforms
(`splat_ground_indices`, `splat_mid_indices`, `splat_rock_indices`),
each channel storing the (tier, layer) for that slot. Adds ~15 lines
of shader + GDScript; lets a biome's 3 slots live in any tiers.

### Runtime Texture2DArray construction (5a)
Godot 4.5 doesn't serialize Texture2DArray with external Image refs
cleanly — `_images = Array[Image]([null, null, ...])` even with
`FLAG_BUNDLE_RESOURCES`. Probed it directly, confirmed via
[godot-proposals#10601](https://github.com/godotengine/godot-proposals/issues/10601).
Moved array construction into `ScaleWorld._build_v2_arrays_if_needed`
at scene init: reads `layer_manifest.json`, loads each layer's PNG,
calls `create_from_images([imgs])`, sets the result as a
`shader_parameter` on the global material. ~hundreds of ms one-shot;
acceptable.

### Auto-upsample + L→RGB convert in the pipeline (5a)
Source PBR files have mixed resolutions (StableMaterials outputs AO
at half-res, W3 real-ortho outputs 16×16 placeholders, ComfyUI
outputs 1024² albedo/normal) and modes (L vs RGB vs RGBA).
`_ensure_resolution` writes `__upsampled<N>_rgb.png` siblings via
LANCZOS resample + `convert("RGB")`. Originals untouched, idempotent
on rerun.

### Format + mipmap normalization at runtime too (5a)
Even after pipeline normalization, Godot's `.ctex` import re-introduces
per-layer variation (mipmaps generated by import preset; some PNGs
get mipmaps, others don't). `create_from_images` requires uniform
`has_mipmaps()` AND uniform `get_format()` across all layers.
ScaleWorld calls `convert(FORMAT_RGBA8)` + `clear_mipmaps()` on every
image before passing to `create_from_images`. Belt-and-suspenders;
the array regenerates mipmaps internally as needed.

### Slot-pool indirection over raw layer refs (5c)
splat_meta emits `slot` (pool index) not `layer` (raw array layer).
Manifest carries `slot_pool[tier]` mapping pool→raw. v1 pool is
identity (`pool[i] == i`), numbers unchanged. When streaming arrives,
the pool becomes dynamic — biomes page in/out of array slots — and
nothing in the splat files changes. The shader uniform (packed
`(tier, raw_layer)`) is unchanged; ScaleWorld translates at
material-init.

### `shared_material: Material` export on TileTerrain (5a)
ScaleWorld pre-builds a per-tile material instance and hands it to
TileTerrain directly via the new `shared_material` export. Wins over
the pre-existing `shared_material_path: String` (loaded at apply
time). Avoids per-tile `.tres` re-loads; lets ScaleWorld set per-tile
shader_parameters before the mesh is finalised. Path-based fallback
still works for pre-Axis-6 paths.

## Pitfalls hit

All landed in `docs/reference/PITFALLS.md` (#5 + #5b):

1. **Texture2DArray.tres doesn't bundle external Image refs.** Use
   runtime construction. (`#5b`.)
2. **Mixed image formats across array layers** (L8/RGB8/RGBA8) →
   `create_from_images` err=31. Fix: `img.convert(FORMAT_RGBA8)` on
   every layer.
3. **Mixed mipmap state across array layers** → same err=31. Fix:
   `img.clear_mipmaps()` on every layer.

Symptom for #2 + #3 is identical — same err code, no per-layer
detail in the error message. Diagnostic snippet to print per-layer
`get_format()` + `has_mipmaps()` lives in PITFALLS #5.

Also hit + fixed during execution (not separate pitfall entries):

4. **`_set_mode("walk")` takes int enum, not string.** Cost: one
   capture iteration. Fixed by passing `CameraMode.WALK` value (0)
   directly.
5. **Walk camera Y=20 puts camera underground at scale_demo's
   500-1027m elevation range.** Cost: one capture iteration. Fixed by
   raising to Y=800.

## What this stage did NOT do

- **No streaming.** Slot pool is identity; all biomes resident. The
  architecture (CPU-side pool indirection in ScaleWorld + slot-pool
  field in splat_meta) is streaming-ready. Streaming adds: LRU
  eviction policy + async layer-load + per-frame pool updates. Plan
  for it when biome counts exceed ~30.
- **No per-pair feather widths.** All boundaries use the same
  `--feather-width-m`. Per-pair authoring is a small addition.
- **No 4-way junction handling.** A tile bordered by 4 different
  biomes drops the 4th in NESW iteration order. Rare; splats have
  only 4 channels by design.
- **No iso/topdown per-biome shading.** Iso/topdown still use the
  single-material `material_view_iso.tres` / `material_view_topdown.tres`,
  losing biome distinction in those views. To get per-biome iso/
  topdown: author per-view biome materials or wire per-view
  shader_parameter overrides on the global terrain material. Axis 4
  ↔ Axis 2 cross-cut follow-up.
- **No biome-pack swap demo.** The architecture supports per-game
  biome packs (swap catalog + regenerate). Not exercised in this
  session beyond the W4 5-biome set.

## What unlocks now

### Immediate
- Soft biome transitions, art-directable per-world via `--feather-width-m`.
- Adding a biome = drop kit + register in catalog + regenerate. No
  shader/script edit.
- Adding a resolution tier = catalog + ~30 lines of shader/GDScript
  changes per the portability doc.

### Near-term (parked, ready when needed)
- Streaming. Slot-pool indirection is in place; just needs an
  eviction policy + async loader.
- Per-game biome packs. Architecture works today; exercise it when
  the first game ships with a different palette.
- Procedural biome assignment (Axis 2 follow-up). Tile meta.json
  biome field is the contract; replace the hand-coded layout with a
  heightmap-derived rule.

### Strategic (per ROADMAP)
- **Strand A — 3D depth** — real-game scale, decoration, per-view per-biome.
- **Strand B — Output models** — offline bake renderer, 2D-game integration.
- The Axis 6 shader is a strong building block for Strand A (it's the
  canonical scale-axis renderer) and a weak one for Strand B (a bake
  would render through it once and capture a static image).
