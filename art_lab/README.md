## Why This Design

Do not build the spell/VFX shader pipeline around a claimed "AI shader generator." There is no Godot-compatible AI spell shader generator worth making the backbone of the asset factory.

Instead:

1. Author a library of parameterized Godot shaders.
2. Let the LLM fill request JSON with colors, radii, speeds, style intent, and role.
3. Generate `.gdshader`, `.tscn`, preview files, metrics, and review packets.
4. Keep only the candidates that survive non-OCR review.

This is auditable, deterministic, performant, and the output ships directly into Godot 4.5 without a translation layer.

## Generate One Shader

```powershell
python art_lab\tools\shader_compile_preview.py --request art_lab\shaders\generated\examples\arcane_shield_ring.request.json
python art_lab\tools\shader_compile_preview.py --template ring_field_2d --id ring_test --no-render
```

Use `--godot-exe <path>` if Godot is not at `C:\Program Files\Godot\Godot_v4.5-stable_win64.exe`.

`--no-render` skips the Godot preview render. The `.gdshader` and `.tscn` still get written.

## Batch Exploration and Review

`shader_batch_review.py` is the semi-automated LLM workflow. It explores shader parameter variants, renders CPU proxy previews when Godot is not available, scores outputs from pixels, and writes a gallery plus an LLM review packet.

This exists because LLM visual/OCR review is not reliable enough for shader quality. The LLM should iterate from structured metrics and small galleries, not from "reading" screenshots.

```powershell
python art_lab\tools\shader_batch_review.py `
  --batch-id storm_portal_round_001 `
  --count 80 `
  --frames 8 `
  --size 256 `
  --seed 42 `
  --intent "AAA-quality storm, shield, portal, projectile, aura, dissolve spell shaders"
```

Outputs:

```text
art_lab/shaders/batches/<batch_id>/
  gallery.html              # visual review page, sorted by score
  batch_summary.json        # all candidates and metrics
  llm_review_packet.json    # compact top-candidate packet for the next LLM pass
  llm_review.md             # readable handoff
  <candidate_id>/
    <candidate_id>.gdshader
    <candidate_id>.tscn
    request.json            # params + review score
    preview.png
    flipbook.png
    frames/
```

Current scoring uses non-OCR image metrics:

- alpha coverage and silhouette aspect
- brightness and contrast
- colorfulness
- edge/detail energy
- center balance
- animation motion and flicker
- clipping/overfill penalties
- role-specific rubrics for aura, beam, projectile, shield, portal, dissolve, ground, UI, and AOE

LLM iteration policy:

1. Run a broad batch.
2. Read `llm_review_packet.json`.
3. Mutate locally around `keep` and `review` candidates.
4. Reject low-coverage, full-screen, low-contrast, over-noisy, or static outputs automatically.
5. Send only the best gallery/candidate paths to the user for visual review.

## Promote A Review Queue

Use `shader_promote.py` to copy only high-scoring candidates into a compact queue. Diversity filtering keeps the queue from filling with near-identical mutations.

```powershell
python art_lab\tools\shader_promote.py `
  --latest 3 `
  --queue-id review_today_001 `
  --min-score 82 `
  --max-count 24 `
  --diversity-distance 0.22
```

Outputs:

```text
art_lab/shaders/review_queues/<queue_id>/
  index.html
  manifest.json
  review.md
  <candidate_id>/
```

## Score Against References

Put curated images in `art_lab/shaders/reference_sets/<name>/`, then score a batch against that style.

```powershell
python art_lab\tools\shader_reference_score.py `
  --batch-dir art_lab\shaders\batches\storm_portal_round_001 `
  --reference-set storm_projectile `
  --update-summary
```

This writes `reference_scores.json` and `reference_review.md` into the batch. Use it after normal batch scoring: base score catches broken shaders, reference score catches style proximity.

## Evolve Toward References

Use `shader_evolve.py` when you have a target look and want the machine to breed parameter neighborhoods around it. This is the practical version of the genetic-shader idea: selection uses deterministic image features plus the normal role gate, not OCR.

```powershell
python art_lab\tools\shader_evolve.py `
  --reference art_lab\shaders\reference_sets\storm_projectile `
  --batch-id storm_projectile_evolve_001 `
  --template beam_lightning_2d `
  --template portal_swirl_2d `
  --population 36 `
  --generations 5 `
  --elites 6 `
  --frames 8 `
  --size 256 `
  --intent "evolve storm projectile and portal silhouettes toward the references"
```

The output is a normal batch folder with `gallery.html`, `batch_summary.json`, `evolution_summary.json`, and `llm_review_packet.json`, so it can be promoted with `shader_promote.py`.

## Godot Render Pass

When a Godot 4.5 binary is available, run the engine renderer over a candidate or whole batch:

```powershell
python art_lab\tools\shader_godot_render.py `
  --batch-dir art_lab\shaders\batches\storm_portal_round_001 `
  --godot-exe "C:\path\to\Godot_v4.5-stable_mono_win64.exe" `
  --frames 8 `
  --no-headless
```

The wrapper writes `preview_godot.png`, `flipbook_godot.png`, `godot_frames/`, and a `godot_render` block into each `request.json`. Try default headless first; use `--no-headless` if the Windows GPU backend does not produce valid frames.

## Request JSON Shape

```json
{
  "id": "arcane_shield_ring",
  "template": "ring_field_2d",
  "params": {
    "color_inner": [0.33, 0.84, 1.0],
    "radius": 0.42,
    "edge_width": 0.04,
    "rune_count": 12.0
  },
  "preview": {
    "size": [512, 512],
    "frames": 32,
    "duration_s": 2.0,
    "background": [0.05, 0.05, 0.08, 1.0]
  }
}
```

The full set of params for each template is the list of `uniform` declarations in the corresponding `.gdshader`. Use `hint_range` and `source_color` uniforms for new templates so the harness can parse them.
