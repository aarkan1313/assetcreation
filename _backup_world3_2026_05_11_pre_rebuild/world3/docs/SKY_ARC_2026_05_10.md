# Sky Arc

Date: 2026-05-10

The Sky module owns **static celestial content overhead**: stars,
milky way band, sun disk, moon disk + phases, aurora (polar). Distinct
from Weather (dynamic atmospheric state) and Atmosphere (color/scattering).

This arc runs **second** in the post-M24 sequence per
[`M_SEQUENCE_2026_05_10.md`](M_SEQUENCE_2026_05_10.md) — after
Atmosphere, before Water + Weather. Cheap, isolated, and gives early
visible momentum.

## What it produces

Files added to the bundle (per `WORLD3_CONTRACT_2026_05_10.md`):

```
<region_id>/
└── sky/
    ├── starfield.png            ← procedural star positions (real-derived)
    ├── starfield_meta.json      ← per-region celestial orientation
    ├── milky_way.json           ← galactic-band orientation + density
    ├── celestial_bodies.json    ← sun, moon, planets, phases
    ├── aurora_params.json       ← polar regions only
    └── reference_shaders/
        ├── starfield.gdshader
        ├── celestial_bodies.gdshader
        └── aurora.gdshader       ← polar only
```

## What it depends on

- **Atmosphere arc**: sky color gradient comes from atmosphere; sky content sits on top of atmospheric color
- **Terrain Foundation**: latitude + region orientation (where the celestial sphere sits relative to North)
- Nothing else.

## What depends on it

- **Weather arc**: clouds occlude celestial bodies, storms hide sky (compositing rules live in weather state machine)
- Nothing downward — Sky doesn't affect terrain, scatter, or materials

## Source: Track D3 promoted

**Track D3 (procedural night sky from stellar statistics)** is
promoted as Sky's source. Same "real data → statistical signature →
procedural derivative" pattern as M19-M24 terrain. Pull HYG / AT-HYG
catalog data; extract distributions (magnitude, spectral type, density
gradient across Milky Way band); generate **new** star fields with
matching statistics. Real but not Earth — feels astronomically right
without giving away specific constellations.

## Right-sized Ms

### S1 — Stellar statistics extraction

**Goal**: fit per-distribution statistics from HYG v4.2 / AT-HYG v3 stellar catalogs.

Inputs:
- HYG v4.2 (71 MB CSV, CC-BY-SA 4.0) or AT-HYG v3 (Gaia-derived 3D positions)
- Galactic coordinate system (well-documented)

Deliverables:
- `pipelines/sky/stellar_statistics.py` — fits magnitude distribution, spectral-type distribution, density gradient across Milky Way band, double-star fraction
- `pipelines/sky/stellar_distributions.json` — fitted parameters (not per-region; global stellar-population priors)

Exit:
- Fitted distributions visually match real catalog when sampled
- Galactic coordinate system handled correctly (Milky Way band orientation derivable from galactic latitude)

### S2 — Procedural starfield generator + reference shader

**Goal**: generate per-region procedural star field with matching statistics; reference shader for rendering.

Inputs:
- S1 distributions
- Per-region celestial orientation (latitude + season + game-clock time)

Deliverables:
- `pipelines/sky/synthesize_starfield.py` — generates new star positions matching S1 statistics
- `sky/starfield.png` per region (cubemap or equirectangular)
- `sky/starfield_meta.json` per region (orientation + epoch)
- `sky/reference_shaders/starfield.gdshader` — point-sprite or shader-input rendering

Exit:
- Star field renders cleanly at walk mode
- Milky Way band visible at correct orientation per latitude
- Constellations are unrecognizable but density/color reads right

### S3 — Sun + moon + planets manifest + reference shader

**Goal**: sun disk, moon disk + phases, visible planets manifest; reference shader for disk rendering.

Inputs:
- Per-region game-clock convention (consumer-driven; we emit static data)
- Spectral-type → blackbody color mapping (Track D4 utility, inlined here)

Deliverables:
- `pipelines/sky/celestial_bodies_gen.py` — emits sun/moon/planet positions over a reference day-cycle
- `sky/celestial_bodies.json` — disk positions, phases, blackbody colors
- `sky/reference_shaders/celestial_bodies.gdshader` — disk rendering with phase support

Exit:
- Sun moves correctly across sky over reference day-cycle
- Moon shows visible phases that consumer can animate from
- Sun color shifts at sunrise/sunset coupling correctly to atmospheric_lut

### S4 — Milky way band + per-region celestial orientation

**Goal**: full Milky Way band density texture + per-region orientation calculation.

Inputs:
- S1 stellar density gradient
- Galactic-to-equatorial coordinate transforms

Deliverables:
- `sky/milky_way.json` — band orientation + density curve per region
- `pipelines/sky/milky_way_gen.py` — orientation from latitude

Exit:
- Milky Way band appears correctly oriented per latitude (e.g. overhead band in tropical regions, low band near poles)
- Density curve visible in walk mode

### S5 — Aurora (polar regions) + conformance

**Goal**: aurora module for polar regions + sky-arc conformance.

Inputs:
- Real aurora photography for statistical reference
- Polar region detection from `height_meta.json` latitude

Deliverables:
- `sky/aurora_params.json` — only present in polar regions; null in others
- `sky/reference_shaders/aurora.gdshader` — aurora rendering
- Per-(time-of-day × latitude × hemisphere) walk-mode conformance scenes
- Polar-region-specific aurora conformance scenes
- M13 promotion gate accepts sky artifacts

Exit:
- All conformance scenes pass at walk mode
- Iso mode correctly clips sky (no sky data emitted/rendered for iso)
- Topdown mode correctly skips sky entirely
- Sky arc passes M13 promotion gate

## Exit criteria (whole arc)

- Every region (non-polar + polar) emits valid `sky/` directory
- Reference shaders render correctly at walk mode
- Iso mode shows sky as faded background or skipped (per-region policy)
- Topdown mode skips sky entirely
- Sky × Atmosphere coupling works (sky content sits correctly on atmospheric gradient)
- All five Ms passed M13 gate

## Risks

- **R1 — "Real but not Earth" constraint is hard to maintain.** If procedural starfields look too random (no recognizable density structure) they read as noise; too structured (Orion-like patterns) they read as Earth. Mitigation: S1 distributions tuned against visual review; S2 outputs visually reviewed against "feels astronomical, doesn't trigger recognition."
- **R2 — Per-mode opt-out for sky is subtle.** Iso mode often clips sky but sometimes shows it (high-tilt iso views); topdown never shows it. Mitigation: per-mode policy declared in `meta.json`, consumer-respected.
- **R3 — Game-clock convention is consumer-side.** Sun/moon positions emit relative to reference day-cycle; consumer translates to game time. Risk: consumers handle this inconsistently. Mitigation: documented contract in S3.

## Estimated effort

5 Ms × 1-3 sessions each = ~5-15 sessions / ~1-3 months.

Smaller arc than Atmosphere or Weather — Sky is isolated and benefits
from clean Track D3 source data.
