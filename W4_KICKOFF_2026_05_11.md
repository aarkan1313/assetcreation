# World4 — kickoff inventory + plan

> W3 had the right components, the wrong primitive. The plan-as-N-biomes
> approach where every biome is its own height generator was a dead end —
> we hit the wall when adjacent bundles encoded at incompatible elevation
> baselines and the streamer rendered tiles as flat color blocks at 200m
> vs 800m cliffs.
>
> W4 starts from M11's invariants (one source of truth for geometry,
> uniform render path, biome = style choice over geometry) and rebuilds
> the streaming pipeline around them. W3 stays as archive + parts depot.
>
> **The end state hasn't changed:** OpenTopo DEMs as geometric spine,
> procedural amplification informed by DEM features, ComfyUI textures +
> photoreal satellite + shader stylization producing biomes that read as
> fantasy (lava wastes, crystal fields, swamps), all streaming around a
> camera in an infinite-ish world. **The architecture has to change** to
> deliver that.

## What W3 got right (carry forward to W4)

### 1. M11 fourway — the visual quality bar

`world3/pipeline/build_m11_fourway_corner_proof.py` and the rebuilt
`world3/pipeline/m11_bundle_lib.py` produce a per-bundle artifact set
that renders correctly when fed into `World3AutoReviewTour`. The
artifact shape is the **right contract** for a bundle:

- `heightmap.png` (16-bit, world-meter encoded)
- `material.tres` (ShaderMaterial with macro + valid_mask + splat + 5×7
  slot textures bound)
- `layers/render_albedo.png` (per-pixel macro composited from 5 slot
  albedos × splat with M11-style per-slot tinting)
- `layers/splat_weights_rgba.png` (4 explicit channels grass/dirt/
  rock_light/rock_dark; snow = implicit remainder)
- `layers/source_valid_mask.png`
- `layers/{shrub_carryover, dry_grass_density, soil_exposure,
  rock_cluster, fantasy_crack, wash_line, no_scatter}_mask.png`
- `meta.json` with elevation_min_m / elevation_max_m / world_size_*_m

Keep this shape. W4 emits the same artifacts; only the *production*
pipeline above it changes.

### 2. The shader (`terrain_splat_unified.gdshader`)

657 lines, M11 fourway tuned, supports source_macro_albedo +
splat_weights + 5-slot blending + hex tiling + macro/detail layering.
Works with the M11 review tour render path. Carry over as-is.

### 3. `m11_bundle_lib.py` — the generator library (mostly)

Per-pixel macro compositing (5 slot albedos via splat with M11-style
tinting) works. Splat generation works. Per-bundle .tres emit works.
Carry over as-is. Two tweaks needed for W4:

- The `BundleSpec.elev_min_m`/`elev_range_m` should be DRIVEN by the
  world heightfield slicer, not per-biome. Library is fine; callers
  change.
- The fourway path is a *single* bundle shape; W4 may not need it
  initially (one global DEM → no need for fourway-style 4-domain
  blending within one bundle). But keep it — useful for hand-authored
  feature bundles.

### 4. `ChunkLoader.gd` — the renderer (M11-tour style)

ONE loader, ONE source, ONE material, world-coord chunk grid. This is
the proven render path. M11 fourway renders correctly through it. W4
keeps this exactly; the bundle-paged variant (`WorldChunkLoader.gd`
written today) extends it without breaking the M11 invariant: each
chunk still gets ONE material, ONE source — they're just resolved per
chunk from "which bundle owns this chunk's world center."

### 5. `World3AutoReviewTour.gd` render setup pattern

The `_setup_terrain` + `_apply_source_macro_overrides` sequence (load
material, duplicate, set `review_*` shader params, explicitly re-bind
`source_macro_albedo` via RuntimeImageCache) is the only path that
makes the macro render correctly after duplicate(). W4 reuses this
verbatim per chunk (the `WorldChunkLoader._build_chunk_material`
function already does this).

### 6. OpenTopo / DEM cache + tooling

**657 raw DEMs, ~65 GB on disk at `d:/assets/dems/`.** Plus a real
pipeline to fetch / catalog / tile-stitch them:

- `pipelines/terrain/fetch_regional_stac.py` — STAC providers for
  ArcticDEM, REMA, LINZ
- `pipelines/terrain/import_dem.py` — DEM import to standard format
- `pipelines/terrain/tile_stitch.py` — multi-tile stitching
- `pipelines/terrain/bulk_fetch_to_cache.py` — bulk pulls
- `pipelines/terrain/build_master_catalog.py` — catalog generation
- `pipelines/terrain/catalog_search.py` — query the catalog
- `world3/data_catalog.json` — current catalog

This is huge. W4 **starts** with the DEM cache. Heightfields come from
here, not from `procedural` per-biome generators.

### 7. landlab erosion (smoke-tested)

`pipelines/terrain/landlab_smoke_test.py` already runs in isolated
venv (`pipelines/terrain/.venv/`). Demonstrated 60-step erosion on a
128×128 @ 30m FastNoise heightmap, relief 135.8→109.2 m. This is the
M19/M20 "kernelize DEM into procedural amplification" engine, ready
to use.

### 8. ComfyUI / aaa_texture pipeline

`pipelines/textures/aaa_texture.py` and the surrounding kit. Built the
ComfyUI textures M11 fourway uses. Whole world of supporting tools
(palette_lock, kit_generator, detail_pyramid, etc.). Carry over —
this is layer 3 of the W4 stack.

- FLUX.2-klein-9B model stack: ae.safetensors + Redux + SigLIP +
  Qwen3-8B (per `pipelines/textures/FLUX2_KLEIN_9B_SETUP_2026_05_10.md`)
- 31 catalog materials already shipped (`world3/materials/catalog.json`)
- BIOME_KIT_SLOTS mapping (alpine/desert/tundra/grassland/
  temperate_forest → 5 slot materials each)

### 9. Specific lessons learned (memory entries that carry over)

- `quality_over_coverage` — polish existing scenes, don't build more
- `flux_fill_redux_model_stack` — the non-obvious FLUX dependencies
- `tile_prompt_poison_pill` — "tileable seamless texture" wording is
  FLUX-tuned, breaks Chroma/SD3.5/Qwen
- `isolated_venv_per_lane` — one venv per pipeline lane
- `nvdiffrast_blackwell_build` — cached wheel for RTX5090 builds
- `regional_dem_stac_unlock` — ArcticDEM/REMA/LINZ via providers'
  open S3 + STAC

All of these still apply in W4.

## What W3 got wrong (don't carry forward)

### 1. Plan-as-N-biomes primitive

`world_plan_schema.json` makes each biome a height generator. That
forces per-biome elev_min/elev_range, which forces F.3.1 contiguity
hacks, which still produced 600m cliffs because byte-equal edges
aren't world-meter-equal across mismatched encodings.

**Replace with:** plan declares ONE world heightfield source (a real
DEM region or one global procedural). Biomes become *style assignments
over the heightfield*, not generators of it. F.3.1 goes away because
the source is continuous by construction.

### 2. `world_plan_to_bundles.py` iterator

Emits one independent procedural request per tile. F.3.1 patches edge
mismatch after the fact. Wrong primitive.

**Replace with:** a slicer that takes a global heightfield + biome
layout and emits per-tile *views* into the heightfield. Each tile is
a "crop + biome assignment" not an "independent generation."

### 3. `MultiBundleStreamer.gd` (the F.7 streamer)

N ChunkLoaders, one per bundle, each with its own material. The
`duplicate()` path drops the macro binding silently → flat color
blocks. Hard seams between bundles' chunk grids. ~600 chunks rebuilt
on camera move → lag.

**Replace with:** `WorldChunkLoader.gd` (written today). One loader,
one chunk grid, bundles paged in/out as cache entries keyed by
bundle_id, per-chunk material resolved from chunk's owning bundle.
Already written; ready to test against a W4 plan.

### 4. F.3.1 edge-contiguity hack

Trying to thread heightmap edges between independent procedural
generators. Becomes unnecessary when the source IS continuous (real
DEM or single global procedural).

**Replace with:** delete. The slicer takes contiguous slices of a
contiguous source.

### 5. The 5-biome procedural starter plan as a "quality bar"

It was supposed to be a smoke test for the iterator. It was never a
realistic quality bar. The cliffs and flat color blocks captured
2026-05-11 prove this.

**Replace with:** the new quality bar = "Gloss Mountain DEM region
sliced into a 5×5 tile streaming world that renders like M11 fourway,
tiled." Real geometry, real continuity, M11-style materials per tile.

## What's actually new in W4 (the design work)

### A. World plan v2 — heightfield-first

```json
{
  "schema_version": 2,
  "id": "starter_gloss_real",
  "bounds_m": [1280.0, 1280.0],
  "tile_size_m": 256.0,
  "world": {
    "heightfield": {
      "type": "real_dem",                // | "procedural" | "real_dem_amplified"
      "source": "world3/toporeview/gloss_mountain_textured_master/heightmap.png",
      "source_meta": "world3/toporeview/gloss_mountain_textured_master/meta.json",
      "world_crop_m": [0, 0, 1280, 1280],
      "amplification": {                  // optional layer 2 — landlab + procedural
        "type": "landlab_fluvial",
        "params": { ... }
      }
    }
  },
  "biome_layout": [
    {"tile_xy": [0, 0], "biome_kit": "grassland", "stylization": null},
    {"tile_xy": [1, 0], "biome_kit": "alpine", "stylization": "lava_waste"},
    ...
  ],
  "biomes": {
    "lava_waste": {
      "base_kit": "alpine",
      "shader_overrides": { "ember_alpha": 0.3, ... },
      "material_overrides": { "rock_dark": "fantasy_lava_field_controlled" }
    }
  }
}
```

The heightfield is global. Biomes are *style assignments* per tile.
Stylization is a layer 3 thing — pick a base biome kit, then apply
shader/material overrides to make it read as a fantasy variant.

### B. Heightfield slicer

```
heightfield_to_bundles.py(plan):
    global_height = load_heightfield(plan.world.heightfield)
    if plan.world.heightfield.amplification:
        global_height = amplify(global_height, plan.world.heightfield.amplification)
    for tile in plan.biome_layout:
        slice = crop_heightfield(global_height, tile.world_xy_m, tile_size_m)
        biome_def = resolve_biome(plan.biomes, tile.biome_kit, tile.stylization)
        emit_bundle(
            heightmap=slice,
            biome_kit=biome_def.base_kit,
            slot_materials=biome_def.material_overrides,
            shader_overrides=biome_def.shader_overrides,
        )
```

This is the new primitive. F.3.1 edge logic deleted; F.4 transition
audit becomes "do adjacent biomes' material kits blend well" which is
catalog work, not generation work.

### C. Layer 2: DEM-informed procedural amplification

The "kernelize DEM" step. landlab + procedural noise *driven by DEM
features* (slope, drainage, ridges) so the procedural amplification
respects the underlying geometry. Output: a higher-resolution
heightfield that retains the DEM's macroscale structure but adds
game-scale detail.

This is the M19/M20 work from the legacy roadmap, but properly
positioned now. Not blocking V1 (V1 just uses the DEM directly).

### D. Layer 3: fantasy stylization shader

Take a base biome kit (alpine = rocky/snowy materials). Apply shader
overrides:
- `lava_waste` = same geometry, ember alpha overlay, rock material
  swapped to `fantasy_lava_field_controlled` (already in catalog),
  shader's `ember_strength` cranked
- `crystal_field` = same geometry, snow slot swapped to a fantasy
  crystal material (catalog gap; new H.1 work), shader's specular and
  emission tuned
- `swamp` = different shader profile (wet, low-saturation), grass slot
  swapped to swamp grass

The shader work is partial: `terrain_splat_unified.gdshader` already
has slot blending and macro overlays. The new bits are stylization
*parameter packs* per fantasy biome.

### E. The streaming renderer

Already written (`WorldChunkLoader.gd`). One loader, bundle-paged. M11
render path per chunk. With a continuous heightfield underneath, the
cliffs go away. With per-tile biome assignment, each chunk material
binds the owning bundle's stylized material stack. F.3.6 architecture
holds; it just needs a sane plan + slicer feeding it.

## What we explicitly are NOT building in W4 v1

- ❌ Multi-biome boundary blending in the shader (hard tile transitions
  acceptable — F.3.1's complexity went here, was wrong choice)
- ❌ Cross-bundle splat blending
- ❌ Procedural-only worlds (every world must have a heightfield
  source; procedural-as-fallback only for testing)
- ❌ F.3.1-style edge contiguity machinery
- ❌ The N-loader streamer (`MultiBundleStreamer` stays in W3 as
  archive)
- ❌ A new texture pipeline (use what `pipelines/textures/` already
  produces)

## The principle W4 enforces (the one M11 invariant)

> Every chunk in a streaming view, regardless of which bundle owns it,
> renders against ONE source heightmap value (continuous across
> bundles), ONE material binding (the owning bundle's), ONE shader
> parameter set (the M11 review tour's). Uniformity at chunk level;
> variation expressed only in *which* bundle's data fills those slots.

This is what M11 fourway proved works. W3 violated it. W4 enforces it.
