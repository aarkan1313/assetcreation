# Water Arc

Date: 2026-05-10

The Water module owns rivers, lakes, ocean, ice, and water-aware
scatter integration. Water is a **second heightfield** layered on
terrain — same data shape as `height.png`, same chunking, same
coordinate frame.

This arc runs **third** in the post-M24 sequence per
[`M_SEQUENCE_2026_05_10.md`](M_SEQUENCE_2026_05_10.md) — after
Atmosphere + Sky, before Weather. Water benefits from Atmosphere's
mist-over-water coupling existing first.

## What it produces

Files added to the bundle (per `WORLD3_CONTRACT_2026_05_10.md`):

```
<region_id>/
└── water/
    ├── water_height.png          ← per-pixel water surface elevation
    ├── water_type_mask.png       ← river / lake / ocean / wetland / ice
    ├── flow_direction.png        ← 2-channel encoded flow vectors
    ├── water_manifest.json       ← per-feature parameters
    └── reference_shaders/
        ├── water_river.gdshader
        ├── water_lake.gdshader
        ├── water_ocean.gdshader
        └── water_ice.gdshader
```

Plus extensions to `scatter_masks/scatter_manifest.json` for water-aware
scatter rules (riparian zones, no-vegetation in water bodies).

## What it depends on

- **Terrain Foundation**: drainage networks from M20 erosion
- **Atmosphere arc**: mist-over-water coupling (A4 leaves hooks; this arc fills them)
- **Material Catalog**: water material variants per type × per mode
- **Scatter & Features**: water-aware scatter rules
- **Track A2 (bathymetry)**: required for ocean extension; effectively promoted-by-dependency here

## What depends on it

- **Weather arc**: cold weather freezes lakes, rain raises river levels — coupling rules live in weather state machine but reference water type masks

## Right-sized Ms

### W1 — Drainage network extraction from erosion

**Goal**: M20 erosion-derived drainage networks promote to runtime water masks for river/channel features.

Inputs:
- M20 Landlab erosion baked drainage maps per cached region
- M11 feature-mask runtime infrastructure
- Real-DEM hydrology data (USGS NHDPlus where available) for validation only

Deliverables:
- `pipelines/water/erosion_to_drainage.py` — extracts drainage polygons + flow magnitudes
- `water/water_height.png` populated for river/channel pixels (just slightly below terrain surface)
- `water/flow_direction.png` populated for river/channel pixels
- `water/water_type_mask.png` populated with type=1 (river) regions

Exit:
- At least 3 cached real-DEM regions have river network topology that matches real-world river maps
- At least 1 procedural region has plausible river masks from M20 erosion

### W2 — Lake / pond detection

**Goal**: closed depressions emit as lake water bodies.

Inputs:
- M20 erosion drainage + M22 patch-seeded terrain
- Closed-depression detection algorithm (priority-flood or similar; well-known)

Deliverables:
- `pipelines/water/detect_water_bodies.py` — closed-depression finder + depth threshold + minimum-area filter
- `water/water_type_mask.png` updated with type=2 (lake) regions
- Lake `water_height.png` reflects pooled-water surface (flat horizontal plane at sill level)

Exit:
- Lakes correctly detected in test regions (Crater Lake, Yellowstone, alpine tarns)
- No false positives on saddles / shallow basins

### W3 — Ocean / coastal extension

**Goal**: coastal regions emit ocean water where biome_label says "coastal" and bathymetric source data is available.

Inputs:
- GEBCO bathymetry (Track A2 source — pulled if not already cached)
- Sea-level rules per region (0m for present-day Earth defaults)
- Coastline data (OpenStreetMap, USGS DEM coastline products)

Deliverables:
- `pipelines/water/extend_coastal.py` — extends terrain heightmap with bathymetry beyond shoreline; emits ocean water mask
- `water/water_type_mask.png` updated with type=3 (ocean) regions
- `water/water_manifest.json` includes salinity + temperature per ocean body

Exit:
- At least 2 cached coastal regions have correct ocean extension (Olympic Peninsula, Big Sur)
- Inland regions correctly emit no ocean

### W4 — Water type classification + flow direction encoding

**Goal**: full water_type_mask coverage + correct flow_direction encoding.

Inputs:
- W1/W2/W3 outputs
- Climate hints for ice extent (latitude + elevation; deferred to Weather arc if not yet ready)

Deliverables:
- `pipelines/water/classify_water.py` — unified type mask producer
- Flow direction encoded as 2-channel RG (cos/sin) per pixel
- `water/water_manifest.json` finalized with per-feature parameters (flow rate, salinity, opacity, temperature)

Exit:
- All water pixels classified into one of: river / lake / ocean / wetland / ice
- Flow vectors point downhill / match real-world directions

### W5 — Water-aware scatter integration

**Goal**: scatter masks respect water bodies; riparian zones get density overrides.

Inputs:
- M15 scatter mask infrastructure
- W1-W4 water outputs

Deliverables:
- `pipelines/water/water_aware_scatter.py` — modifies scatter density based on water proximity
- `scatter_manifest.json` extensions: per-feature "water-affinity" (avoid / neutral / prefer)
- Riparian zone scatter overrides (denser grass + reeds near rivers)

Exit:
- Scatter conformance scenes show no vegetation in/under water bodies
- Riparian zones visibly different from dryland in scatter density

### W6 — Per-mode water material variants + reference shaders + conformance

**Goal**: per-mode water material variants + reference shaders + water-arc conformance.

Inputs:
- All W1-W5 outputs
- Per-mode `.tres` material variant system (Phase E)

Deliverables:
- `world3/materials/water_<type>_<mode>.tres` for each (water type × view mode)
- `water/reference_shaders/water_*.gdshader` — reference shaders per type
- Water-track conformance scenes (clear-water, muddy-water, ice, riparian, deep-ocean)
- M13 promotion gate accepts water-track artifacts

Exit:
- Water renders correctly at close walk, medium walk, iso, and topdown
- All conformance scenes pass review
- Water arc passes M13 promotion gate

## Exit criteria (whole arc)

- Every region with water emits valid `water/` directory
- Reference shaders cover all four water types
- Per-mode rendering correct (walk shows wet surfaces + reflections; iso shows shape + flow; topdown shows tactical color overlay)
- Scatter integration honors water bodies
- All six Ms passed M13 gate

## Risks

- **R1 — Ice extent depends on climate data from Atmosphere arc.** If Atmosphere isn't ready, W4 defers ice classification to a later pass. Mitigation: W4 emits placeholder ice mask (none) when climate data absent; revisit when Atmosphere is complete.
- **R2 — Bathymetry source data is patchy.** GEBCO covers oceans but resolution varies; some coastal regions have detailed Track A2 data, others have only global GEBCO. Mitigation: W3 ranks regions by source-data quality; cheap regions get high-res ocean, sparse-data regions get coarse.
- **R3 — Closed-depression detection produces false positives on saddles.** Mitigation: W2 includes minimum-area + minimum-depth filters; validates against real lake maps for known regions.

## Estimated effort

6 Ms × 1-3 sessions each = ~6-18 sessions / ~1.5-4 months.
