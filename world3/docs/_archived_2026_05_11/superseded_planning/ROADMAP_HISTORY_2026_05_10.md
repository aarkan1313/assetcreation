## v1 → v2 reframe (2026-05-07)

Original v1 roadmap was DEM analyzer → procedural generator → infinite
world. v2 reframed against concrete quality gaps surfaced through
Phase 1 + Phase 2.

**Long-term direction clarified**: continuous worlds should be
real-data grounded, but not by stretching or endlessly repeating one
finite OpenTopo crop. OpenTopo/DEM stacks are reference, training,
validation, and mosaic inputs. Procedural expansion should learn/
extract landform, material, vegetation-density, drainage, and
transition rules from those sources, then generate or stream
compatible neighboring terrain.

## 2026-05-08 update — operating-model + sequence revision

Two changes since the original v2 reframe:

1. **Single-stream orchestrator/worker model.** The world3 main chat
   is the orchestrator (owns roadmap + most work + cross-cutting
   decisions). The OpenTopo chat is a worker that takes scoped
   handoffs. Replaces the "two parallel pipelines" framing.

2. **Phase F absorbed into M1–M6.** Once we recognized that
   material taxonomy + transitions + splat shader + chunk size are
   interlocked, doing them as a sequential "Phase F → G → H → I"
   was wrong. M1–M6 became the current iteration:
   - M1 — material catalog (orchestrator-led, blocks rest)
   - M2 — transition prototype (worker handoff)
   - M3 — chunk-size sweep (orchestrator, was Phase F.4-sweep)
   - M4 — splat-shader prototype (orchestrator, after M1+M2)
   - M5 — wire streaming + splat into `walk.tscn` (orchestrator)
   - M6 — harden streamed runtime: cache, collision, transition hook, source QA

## Phase A — Texture quality + prompt R&D (DONE 2026-05-07)

The texture pipeline was mature but FLUX missed prompts ~30% of the
time. This phase was experiments + observations, not new code.

Outcomes:
- Reproducible experiment harness: `pipelines/textures/experiment.py`
- Same-prompt sweep on 5 materials → 2 weak cases surfaced (snow stylization, leaf_litter lattice)
- Prompt-permutation sweep on weak cases → both rewritten with decisive winners; 3 new anti-patterns added to cookbook
- Settings sweep: 4 stays default; 6 helps variance-sensitive materials; 8 never wins
- External research (EXTERNAL_TECHNIQUES.md): offset+heal algorithm matches open-source canon
- Applied learnings to weak materials: tundra_ice + desert_canyon_rock prompt rewrites
- Regenerated shipping textures: wgv3_snow, wgv3_forest_floor, wgv3_tundra_ice, wgv3_desert_canyon_rock all at grade A

Exit criteria met:
- Prompt-accuracy qualitatively higher (4 weak materials lifted to A grade)
- New technique adopted (variants-count tuning rule)
- Cookbook doubled in size

## Phase A polish — pipeline foundation hardening (DONE 2026-05-07)

Bridge between Phase A's prompt R&D and Phase B's upscaling. Workflow
+ tooling improvements that every future material benefits from.

Outcomes:
- **A.7 — Richness QA metric (advisory)**. New `richness` check in `texture_qa.py` that defends against the "smooth-A" failure mode. Calibrated across 122 textures.
- **A.8 — CHORD opt-in PBR backend**. Added `aaa_texture.py --pbr-backend {derive,sm,chord}`. CHORD wins normals + height on hard-edge geometry; loses on rock roughness. Kept opt-in.
- **A.9 — variant_blend rescue tool**. `pipelines/textures/variant_blend.py`: combines N tileable variants into one via softmax-weighted blending. Manual rescue.
- **A.10 — Reference-image anchor mode on flux_seamless.py**. Klein-native img2img with BasicScheduler. `--reference-image` + `--reference-mode anchor` works.
- **A.11 — CHORD + SM-roughness hybrid**. `--pbr-backend chord_sm_rough` runs CHORD for albedo/normal/height/metallic/ao + SM for roughness. Opt-in for Rock-class materials.

Open / parked candidates at the time:
- Auto-rescue mode (lattice detection → variant_blend fallback)
- Promote richness from advisory to hard-gate
- klein-9B Edit (now landed 2026-05-10 as part of FLUX 2 9B bakeoff)
- Honest partial-denoise heal pass audit
- Curated reference photo set for A.10 anchor mode

## Phase E — Per-game-mode material tuning (DONE 2026-05-07)

Decision-locked principle "walk/iso/topdown are different games" implemented.

Outcomes:
- Per-mode material variants: each kit emits `terrain_blend_<kit>_<mode>.tres` for walk/iso/topdown via `emit_per_mode_materials.py`. 15 .tres committed (5 kits × 3 modes).
- Tuning targets per mode:
  - walk: world_uv_scale 0.4 (~2.5m repeat), normal_strength 1.2, macro_value 0.05, blend_sharpness 12.0
  - iso: world_uv_scale 0.1 (~10m repeat), normal_strength 1.0, macro_value 0.15, blend_sharpness 8.0
  - topdown: world_uv_scale 0.02 (~50m repeat), normal_strength 0.4, macro_value 0.35, blend_sharpness 4.0
- Per-mode capture sweeps validate clear visual differences (walk = surface detail, iso = mid blend, topdown = color blocks)

## Phase F — Multi-tile / continuous world (ABSORBED into M1-M6)

Long-term goal: walk off region edge, enter adjacent region seamlessly. Phase F was absorbed into the M1-M6 sequence (2026-05-08) after recognizing the components were interlocked.

Phase F research findings preserved: 256 m chunks for walk-mode streaming, `ChunkLoader.gd` walker-driven chunk load/unload around an XZ position, source-height repeat artifacts policy.

The OpenTopo pilots opened a parallel branch feeding the main terrain

- Fused real-place scenes/maps from DTM, orthophoto, NIR, canopy, LAZ

## Far-end direction (post-M1-M5 option registers)

Three forward-looking option registers describe what the system could
expand into next. Now lives in the queued-options docs
(`FUTURE_WORLD_SOURCES_2026_05_08.md`, `FUTURE_PROCEDURAL_STRUCTURES_2026_05_08.md`)
and the arc docs (Atmosphere/Sky/Water/Weather/Conformance).

### Track A — alternative world sources
Six items (A1-A6, A8 added 2026-05-11): NLCD/Copernicus land-cover, bathymetry + coastal, planetary DEMs, sketch-to-heightmap, fantasy world generators, photo + depth estimation, gaussian splat capture.

### Track B — explorable interiors / structures
Different pipeline shape from terrain (not heightmap-based). 6 sub-categories from single-room caves through full castle/dungeon networks.

### Track C — procedural structure generators
11 structure-generator families (G1-G11): branching, cellular/Voronoi, reaction-diffusion, fractals, aggregates, layered, filaments, folded surfaces, diffusion, tilings, wave patterns. Recommended Tier 1: G1 trees + G7 grass + G5 scree.

### Track D — astronomical data sources (added 2026-05-10)
Six items (D1-D6). D1 promoted to M33 (later rebased into Weather arc as WX-1) as cloud-system source. D3 promoted to Sky arc as procedural night sky source.

### Cross-cutting integration constraints

The Track A/B/C/D docs describe what M1-M5 should keep
source/output-agnostic so no track requires retrofitting later:

- **M1 catalog**: include `material_role` (ground, vegetation, crystal, fabric, decal, structural) and `geometry_class` (2d_texture, instanced_mesh, field_scatter, decal, volumetric).
- **M2 transitions**: data model supports `transition_type` beyond "2D blended strip" — density gradient, scatter taper, edge decoration, threshold.
- **M3+M5 chunks**: per-chunk format extensible (named layers, not fixed-shape struct).
- **M4 splat shader**: long-term unified shader could absorb interior-floor splatting and per-mesh per-pixel mixing.

## Phase order

Originally A → B → D → C → E → F. Actual order shipped: A (done) → A polish (done) → B (done) → C (done) → D (done) → E (done) → F absorbed into M1-M6.

C/D/E all landed in a single 2026-05-07 evening session. D's kit-binding bug surfaced by the C-D handoff capturing a regression on chaparral/grassland regions; the fix mechanism (`deploy_kit_to_world3.py`) ended up being the same plumbing E needed for per-mode emission.

## Operating principles (preserved)

- **One thing at a time.** Each phase has clear scope and exit criteria. We don't move on until the current phase's checklist is done.
- **Improve what we have before extending.** Quality of existing outputs (textures, kits, materials) before more breadth.
- **Research before building.** Texture quality and upscaling both benefit from external survey before committing to a workflow.
- **Defer LOD and kernels.** LOD decided when performance forces it. Kernels are long-term direction but not 2026 priority.
- **Document as we go.** New decisions in DECISIONS.md, new surprises in LESSONS.md.

## Deferred (preserved)

- **LOD**: decide when performance forces it. Probably during multi-tile loads.
- **DEM analyzer / kernels**: long-term goal but no current pressure.
- **Procedural generator**: dependent on kernels (now in M19-M24 arc).
- **Real water / sea level / scatter / vegetation**: gameplay layer per old framing; water now committed in Water arc, scatter in M15.

## What this history tells you that the canonical roadmap doesn't

Useful patterns to remember:

1. **Phase F absorption** taught us that "sequential phases" is wrong when components are interlocked. The arc-based long-term plan inherits this lesson (Atmosphere/Sky/Water all depend on each other in specific ways; sequenced by dependency, not by linear timeline).
2. **A.7 advisory→hard-gate progression** is the right pattern for new QA metrics. Land as advisory, watch, then promote.
3. **Phase D kit-binding bug** was caught by Phase C-D handoff captures. Cross-phase capture review surfaces integration bugs that single-phase review misses.
4. **A.10 IP-Adapter pivot** (3 attempts to land, ended up using klein-native img2img instead of the original IP-Adapter plan) showed orchestrator handoff specs can be wrong; trust execution feedback over plan.
5. **Repeated-source tiling demotion (2026-05-09)** was a methodology correction that came from visual review. M10 terrain seam integration is the production-facing path.
