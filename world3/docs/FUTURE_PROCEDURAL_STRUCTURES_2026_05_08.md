This doc maps a **third generator family** beyond terrain and
interiors: structure generators for natural/synthetic patterns that
don't fit the heightmap+texture mold. Trees, crystals, cracks,
cellular packings, lattices, branching, layered, folded, etc.

These are the things a heightmap can't describe — they live ON terrain
or AS terrain features, but their generative logic is fundamentally
different.

NOT a plan. An option register. Pick from this when M1–M5 closes and
the orchestrator asks "what next."

---

## Why this matters for world3

Today's world3 pipeline is roughly:

```
heightmap (DEM/proc) + material kit + transition library + splat shader
                                                         + chunks/streaming
                            → playable terrain
```

That covers **ground**. Anything that lives ON the ground (vegetation,
crystal clusters, rock formations, cracks, mineral deposits) or
embedded IN the ground (caves, lava tubes, rock strata) needs a
different generator. The props pipeline currently handles **discrete
single objects** (one mesh, place at a point); it doesn't handle
**fields** (a forest, a crack network, a crystal lattice) or
**structures** (a tree's branching, a fold of fabric, a fractal
coastline).

The generator family captured here fills that gap.

The connection to existing work:
- **Material catalog (M1)**: structure generators emit meshes that
  carry materials. New material classes = new entries.
- **Transition library (M2)**: structure-meets-terrain transitions
  (tree-shadow ground, crack edges, crystal base scree) are real
  transition pairs.
- **Splat shader (M4)**: scatter density (where trees go) reads
  naturally as a splat channel.
- **Chunks (M3)**: structure scatter has to chunk too. Per-chunk
  scatter density mask + per-chunk mesh population.
- **POI markers (Track B)**: structure clusters can be POIs (a single
  giant crystal formation, a hero tree, a notable rock outcrop).

So the work is parallel infrastructure, not a fork.

## The taxonomy of structure generators

These cluster into ~10 families, ordered from "most reusable in worlds
we'd actually build" to "most exotic / specialized." Each family has
known generators, free/cheap implementation paths, and rough
cost/value notes.

### G1. Branching (trees, rivers, lightning, vessels, mycelium)

**What**: anything that branches recursively from a stem or trunk.

**Generative logic**: L-systems (Lindenmayer), space colonization
(Runions algorithm — "the leaves attract growth"), DLA
(diffusion-limited aggregation), recursive subdivision with
randomness.

**Examples in worlds**:
- Trees + bushes (most useful by far)
- River networks (terrain-coupled)
- Crack networks on rock / dried mud / ceramic
- Lightning bolts (instantaneous VFX)
- Coral / sea fans
- Mycelium / fungal networks (cave + forest decoration)
- Lichen + moss spread patterns
- Vein-like mineral deposits in rock

**Free/cheap tools**:
- **SpeedTree** — commercial but indie tier; tree-specific, very high
  quality
- **Modeling-the-tree** open-source repos (search "L-system tree
  generator")
- **The Grove** for Blender (paid, very good)
- **Sapling Tree Gen** (Blender built-in addon, free, decent)
- **Houdini** (free apprentice tier; ProcGen for rivers, trees,
  fractals)
- **TreeIt** (free standalone, exports to game engines)

**Pipeline shape**:
- Generator emits skeleton + mesh + LOD set.
- World3 places via per-chunk scatter density mask (M4 splat-driven).
- Each species = one or more material refs from the catalog.

**Cost/scope**: medium. Tree gen alone is one focused track (several
sessions to ingest a generator + bake LOD + integrate). But trees are
the highest-impact addition for any world that has plants.

**Value**: HIGH. Almost every game world needs vegetation.

### G2. Cellular / Voronoi (crystals, foam, packings)

**What**: space-filling structures generated by point-set distance
fields. Voronoi diagrams, Delaunay triangulations, foam, cracked mud,
giraffe spots.

**Generative logic**: place seed points (random / Poisson disk /
blue-noise), compute regions per point. Vary by metric (Euclidean,
Manhattan, Chebyshev) for different visual styles.

**Examples in worlds**:
- Crystal clusters (cave, ice cave, geode interiors)
- Hex columnar basalt (Giant's Causeway, volcanic landscapes)
- Cracked dry lakebed
- Honeycomb / wasp nest
- Soap-bubble surfaces
- Tiger-stripe / leopard-spot patterns on creatures
- Cell membranes / packed cells (biological scenes)
- Cobblestone roads
- Peeling paint patches
- Insect compound eye lattices

**Free/cheap tools**:
- Standard Voronoi libraries: `scipy.spatial.Voronoi`, `geogram`,
  `voro++`
- **Substance Designer** (commercial but indie tier) has Voronoi
  patterns as a primitive
- Blender's "Voronoi Texture" node + geometry-nodes Voronoi mesh
- Houdini ProcGen Voronoi
- Many open-source Python implementations

**Pipeline shape**:
- 2D Voronoi → texture mask or splat channel.
- 3D Voronoi → instanced cell meshes (crystal clusters, basalt
  columns).
- Per-cell randomization (rotation, scale, material variant from
  catalog).

**Cost/scope**: small-medium. Voronoi is well-understood; the work is
in styling output (good crystals look different from good cracks
from good cells).

**Value**: HIGH for specific environments (caves, volcanic fields,
weathered surfaces, fantasy crystal landscapes). Medium overall.

### G3. Reaction-diffusion / Turing patterns

**What**: simulations producing self-organizing patterns like animal
markings, coral, weathering.

**Generative logic**: Gray-Scott / FitzHugh-Nagumo PDEs run for N
steps from random initial state. Parameter sweeps produce different
visual regimes (spots, stripes, mazes, dots).

**Examples in worlds**:
- Coral / brain coral surfaces
- Animal pelts (tigers, leopards, fish)
- Weathered rust patterns
- Lichen growth
- Mold + spore patterns on damp surfaces
- Some organic alien-feeling environments
- Crop circles (uniform-then-broken patterns)

**Free/cheap tools**:
- Pure shader implementations (Shadertoy has many; can run on GPU
  in Godot)
- Python NumPy for offline baking
- Substance Designer "Reaction Diffusion" node

**Pipeline shape**:
- Bake offline at material-tile resolution.
- Use as albedo, mask, or normal-perturbation input.
- Runtime usage: pre-baked texture; not real-time simulation in
  most cases.

**Cost/scope**: small once you have a working sim. Tuning parameters
is artist-intensive but tractable.

**Value**: MEDIUM. Specific aesthetic (organic / weathered / alien).
Not every world needs it but when it fits, nothing else does.

### G4. Fractals + self-similar (coastlines, mountains, ferns)

**What**: structures that repeat at multiple scales with variation.

**Generative logic**: iterated function systems (IFS), midpoint
displacement, fractal Brownian motion (fBm), Mandelbrot variations
in 2D and 3D (Mandelbulb).

**Examples in worlds**:
- Mountain ridgelines (already done implicitly via DEM noise)
- Coastlines
- Fern fronds (extends into G1 branching)
- Romanesco broccoli textures
- Cloud formations
- Dragon-scale patterns

**Free/cheap tools**:
- FastNoise2 (already in repo; supports fBm, ridged, etc.)
- Mandelbulb 3D / Mandelbulber (free, makes spectacular landscapes)
- Houdini SDF + Mandelbrot nodes
- Many shadertoys

**Pipeline shape**:
- 2D: heightmap-style → already integrates with terrain.
- 3D: SDF-based meshes for hero structures (e.g. a Mandelbulb-derived
  alien ruin).

**Cost/scope**: small. fBm is already in our heightmap tools;
expanding to mesh-domain fractals is a research/experiment exercise.

**Value**: MEDIUM. Mostly already covered by terrain noise. Where it
shines: alien / dream / abstract environments.

### G5. Aggregates / particle settling (rubble, scree, pebbles)

**What**: piles of discrete objects, naturally settled or scattered.

**Generative logic**: rigid-body simulation (Bullet, Jolt, Bullet's
btSoftRigidDynamicsWorld) OR Poisson-disk packing OR sphere packing
algorithms.

**Examples in worlds**:
- Scree slopes at cliff bases
- Pebble beaches
- Rubble fields (war / ruin)
- Treasure piles (gold coins)
- Fruit / seeds in baskets
- Stone walls (semi-aggregate)
- Boulder-strewn deserts

**Free/cheap tools**:
- Godot's built-in physics (run sim once, bake transforms)
- Blender Cell Fracture + rigid-body sim (free, very good)
- Houdini Bullet
- Pure-Python sphere packing libraries

**Pipeline shape**:
- Pre-bake scene: spawn N objects, sim for K seconds, freeze
  transforms.
- Export as instanced mesh transforms (per-chunk scatter list).
- Runtime: instanced rendering, no physics needed.

**Cost/scope**: small for pre-baking. The art direction (which
boulders, which scale variation) is the time sink.

**Value**: HIGH for any world with cliffs, ruins, or shorelines.
MEDIUM otherwise.

### G6. Layered / banded (rock strata, agate, sediment)

**What**: stacked layers with vertical variation. Sedimentary rock,
agate banding, cliff stratification, glacier ice layers.

**Generative logic**: Y-axis-conditioned noise + per-layer color/
texture LUT. Can be 1D noise (banded) or 2D noise warped along Y
(folded layers in cliffs).

**Examples in worlds**:
- Cliff-face stratification
- Canyon walls (think Antelope Canyon, Bryce)
- Ice cliff layering
- Tree rings on cut stumps
- Onion-layer interiors (planetary cross-sections)
- Sliced agate / geodes
- Layered cake — good for stylized/fantasy

**Free/cheap tools**:
- Substance Designer "Stratification" patterns
- Procedural shaders (multiple noise layers, mask by Y coordinate)
- Houdini ProcGen

**Pipeline shape**:
- Shader-driven (per-pixel Y check) — runtime.
- Or pre-baked into material variants for cliff regions.

**Cost/scope**: small. Mostly shader work + parameter tuning.

**Value**: MEDIUM-HIGH. Specifically high for desert / canyon /
mountain games. Adds substantial visual variety with low cost.

### G7. Filaments / fibers (hair, grass blades, fabric)

**What**: many thin elongated objects with wave/wind-like motion.

**Generative logic**: Hair systems (Blender hair particles, Unreal
Groom), grass shaders (instanced billboard / mesh quads), cloth
simulation for fabric drapes.

**Examples in worlds**:
- Grass blades (high-quality close-up grass)
- Hair / fur on creatures
- Cobwebs
- Hanging vines
- Reeds / wheat / cattails
- Tassels, ropes, frayed cloth
- Fabric drapes (banners, curtains, tapestries)
- Fishing nets

**Free/cheap tools**:
- Godot built-in particles + custom mesh shaders
- Blender hair systems → bake to game-ready particle textures
- Open-source grass shaders (many on GitHub)
- Marvelous Designer (commercial; cloth specialist)

**Pipeline shape**:
- Per-blade mesh + GPU instancing OR billboard cards.
- Wind-shader integration.
- Per-chunk density mask.

**Cost/scope**: small for grass (existing tools); medium for hair
(more authoring); large for cloth-sim (real-time cloth is hard).

**Value**: HIGH for any walkable world with vegetation. High for
character work too.

### G8. Folded / curved surfaces (drapes, brain cortex, mountain folds)

**What**: smooth surfaces with folds/wrinkles created by compression
or growth.

**Generative logic**: differential growth simulation, surface bending
under load, orogeny (tectonic uplift) sims for mountains.

**Examples in worlds**:
- Mountain ranges with fold structure (visible in real geology —
  Appalachians vs young Alps)
- Brain coral
- Intestinal villi
- Leather wrinkles
- Cabbage / lettuce leaves
- Coral brain coral

**Free/cheap tools**:
- Blender geometry nodes (Lloyd's relaxation, surface field bending)
- Houdini cloth/relax solvers
- Shader-based (normal-map bumps with directional bias)

**Pipeline shape**:
- Mostly shader/normal-map work for far-mid views.
- Mesh-level for hero close-ups.

**Cost/scope**: medium. Folded surfaces are subtle to get right; the
math is non-trivial.

**Value**: MEDIUM. Specific aesthetics (organic alien, biological,
fantasy mountainous).

### G9. Diffusion / accretion (dust, frost, mineral deposits)

**What**: patterns formed by particles arriving and accumulating on
a surface.

**Generative logic**: diffusion-limited aggregation (DLA), random
walks, Eden growth, ballistic deposition.

**Examples in worlds**:
- Frost on windows / cold metal
- Dust accumulation on ledges
- Mineral deposits in pipes
- Stalactites / stalagmites (cave decoration)
- Salt encrustation
- Lichen colonies
- Snow drifts (small scale)
- Bullet decals at point of impact (not really natural but same math)

**Free/cheap tools**:
- DLA implementations are abundant (Python, JavaScript, shader)
- Substance Designer DLA pattern
- Custom shaders for runtime ice formation

**Pipeline shape**:
- Pre-bake patterns into masks / decals.
- Decal layer on existing materials.

**Cost/scope**: small. DLA is well-understood; output goes through
decal pipeline.

**Value**: MEDIUM. Specific environmental detail; not core but adds
polish to caves, abandoned places, cold environments.

### G10. Tilings + tessellations (Penrose, Islamic, Escher, hex)

**What**: regular or aperiodic tilings of 2D plane, sometimes
extended to 3D.

**Generative logic**: explicit tile placement rules. Wave Function
Collapse for aperiodic tiling. Penrose tile geometry for non-periodic.

**Examples in worlds**:
- Decorative floors (palaces, temples, mosques)
- Stained glass
- Mosaic patterns
- Brick walls (the simplest tessellation)
- Fantasy floor patterns (magic-circle mandala-like)
- Ceiling decoration
- Pavement / road textures

**Free/cheap tools**:
- Many open-source WFC implementations
- Procedural shaders for hex / brick / quad tessellations
- Manual authoring + variation rules

**Pipeline shape**:
- Mostly material-level (texture or shader).
- For 3D structures (e.g. a Penrose-tiled floor with mesh-level
  detail), bake to mesh + LOD.

**Cost/scope**: small for shader-based; medium for mesh-based.

**Value**: HIGH for built environments (castles, temples,
city streets). Track B (interiors) work uses these heavily.

### G11. Wave / vibration (Chladni, ripples, dunes)

**What**: patterns from wave propagation or vibration on a surface.

**Generative logic**: Chladni equations (sand on vibrating plate),
ripple noise, dune formation simulations.

**Examples in worlds**:
- Sand dunes (heightmap-domain — already partly covered)
- Water ripple patterns
- Sand patterns from wind
- Plant arrangement under vibrational stress (rare but real)

**Free/cheap tools**:
- Chladni shader (many shadertoys)
- Wave-equation solvers for water
- Simple 2D wave propagation in NumPy

**Pipeline shape**:
- Mostly heightmap-domain, plugs into existing pipeline.
- Or shader-based for water ripples.

**Cost/scope**: small.

**Value**: LOW-MEDIUM. Mostly subsumed by terrain noise + water
shaders.

## Cross-cutting integration with M1–M5

Even though structure generators are out-of-iteration, what's being
built now affects how easily they slot in later. Specifically:

### M1 (catalog) implications

The catalog should:
- NOT bake "ground material only" assumptions. Every G-family
  produces materials (tree bark, crystal facets, fabric, scree
  pebble) that might enter the catalog.
- Include `material_role` field: `ground`, `vegetation`, `crystal`,
  `fabric`, `decal`, `structural`, etc. Lets shader code know how
  to bind it (per-vertex vs splat vs decal vs instance).
- Include `geometry_class` field: `2d_texture` (current default),
  `instanced_mesh`, `field_scatter`, `decal`, `volumetric`, etc.

If the catalog handles these fields gracefully, future G-family work
adds entries instead of needing a parallel catalog.

### M2 (transitions) implications

Transitions are not just material-to-material 2D blending. They also
include:
- Structure boundary (forest edge — trees thinning out)
- Structure-density gradient (scree gets denser approaching cliff base)
- Material-meets-structure (grass meets tree-shadow ground; rock
  meets crack network)

The transition data model should support `transition_type` beyond just
"strip" — also "density gradient," "scatter taper," "edge decoration."
Don't bake "transition = 2D blended strip" into the schema.

### M3+M4+M5 (chunks + splat + streaming) implications

Per-chunk data needs to include:
- Heightmap (already have)
- Splat weights (M4)
- **Scatter density mask per structure type** (forthcoming)
- **Mesh population list** (per-chunk instanced meshes for trees,
  rocks, etc.)
- **Decal placement** (lichen patches, cracks, weathering decals)

All of these are per-chunk, all stream the same way. Keep the
chunk-data format extensible (e.g. "chunk_data.json" with named
layers, not a fixed-shape struct).

### Track B (interiors) implications

Interiors heavily use G2 (Voronoi for stone walls), G6 (stratification
for cliffs / cave walls), G9 (diffusion for stalactites / dust), G10
(tilings for floors). Track B's pipeline benefits if structure
generators exist before it kicks off.

## Suggested first-target structure generators (when this kicks off)

Don't try to do all 11 families. Pick high-impact ones first.

**Tier 1 (highest leverage, work first)**:

1. **G1 trees** — vegetation is the single biggest visual delta for
   terrain. Even one good tree generator + 5-10 species transforms
   any forest scene.
2. **G7 grass** — close-walking detail. Pairs with trees.
3. **G5 scree / rubble** — adds realism to any rocky terrain.
   Pre-bake-able, low runtime cost.

**Tier 2 (high value, specific environments)**:

4. **G2 Voronoi (crystals, basalt, cracked surfaces)** — caves,
   volcanic, weathered scenes.
5. **G6 stratification** — desert / canyon worlds, cliff-heavy
   scenes.
6. **G9 diffusion (dust, frost, lichen)** — environmental polish.

**Tier 3 (specialized aesthetic)**:

7. **G10 tilings** — built environments, cultural decoration.
   Strongly couples with Track B.
8. **G3 reaction-diffusion** — alien / organic worlds.
9. **G8 folds** — biological / brain-coral / alien terrain.

**Tier 4 (specialized / experimental)**:

10. **G4 3D fractals** — alien / abstract / dream environments.
11. **G11 wave patterns** — mostly subsumed elsewhere.

Recommended starter project (B-stage 0 equivalent):

> Pick G1 trees as MVP. Ingest one free tree generator (Sapling Tree
> Gen or similar), bake LODs, place via M4 splat-driven density mask
> in one test scene. Validates: scatter pipeline + LOD pipeline +
> material catalog with `material_role: vegetation` entries.

Once trees work, the path to grass + scree is short — same scatter +
density-mask pattern.

## Why this isn't six different pipelines

The temptation is to build a separate pipeline per family. Don't.
The unifying abstraction:

```
intent spec → structure generator → mesh + transforms + materials
                                  → per-chunk scatter data
                                  → per-chunk scatter list output
                                  → runtime instanced rendering
```

Generators differ in *how they produce their output*; the *integration
into world3* is the same:
- Output goes into per-chunk data
- Materials reference the catalog
- Density driven by splat masks
- Streamed with chunks
- LOD via standard mesh-LOD pipeline

If the chunk-data format from M3 is extensible, ALL of these slot in
without rearchitecture.

---

## What to NOT do

- Don't try to do real-time simulation for any of these. Pre-bake
  results offline; runtime is just rendering. (Exceptions: water
  ripples, cloth — those are real-time-cheap on modern GPUs.)
- Don't write our own L-system or Voronoi from scratch when good
  free implementations exist. Use them; integrate.
- Don't over-architect. A tree is a mesh + LODs + materials. Treat
  it as such until streaming or scale forces something fancier.
- Don't conflate generator quality with pipeline correctness.
  A bad-looking tree from a working generator is better than a great-
  looking tree we can't generate consistently — the pipeline has to
  produce reproducibly first; quality iterates after.

## Status + next-decision pointer

This doc, like `FUTURE_WORLD_SOURCES_2026_05_08.md`, is an option
register. When M1–M5 closes:

The two parallel post-M5 directions are:

- **Track A (alternative world sources)**: NLCD, bathy, planetary,
  fantasy generators. Extends terrain horizontally.
- **Track C (structure generators — this doc)**: trees, grass,
  scree, crystals, etc. Extends what lives ON terrain vertically.

Track B (explorable interiors) remains its own track but borrows from
Track C heavily (G2, G6, G9, G10).

The single highest-impact single project after M1–M5: **G1 tree
generator + scatter integration** (Tier 1, item #1). It transforms
every walkable world from "terrain" to "place." Closely followed by
NLCD (Track A #1) which gives data-driven biome assignment.

A pairing of "NLCD biome map + tree scatter from biome-class density"
is a uniquely powerful combo: pull a real US region, get land-cover
masks, scatter the right tree species at the right density per biome,
chunked and streamed. That's a ~2-3 session arc to a demo that looks
like a real game world for the first time.
