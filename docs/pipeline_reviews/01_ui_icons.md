## Icon source breakdown

The 135 icons in `ui/icons/` come from **three different sources mixed together**:

| Source | Count | Avg size | What it is |
|---|---|---|---|
| **First-party (synth_icons.py)** | ~37 | 1-3 KB | Procedural line-drawings. Simple flat shapes on transparent BG. |
| **game-icons.net (`ico_gi_*`)** | 55 | 13-22 KB | Real artist-drawn SVGs rendered to PNG. CC-BY 3.0 (attribution required). |
| **lucide (`ico_lucide_*`)** | 22 | small | UI utility icons (chevron, list, user, magnify). MIT. |
| **phosphor (`ico_phosphor_*`)** | 18 | small | UI utility icons (arrows, etc). MIT. |

**Read between the lines:** the procedural baseline produces ~37 simple icons. The remaining 98 are imported from free libraries. **Nothing in the catalog is hero-quality AAA work.** That's by design (the cloud routes were never run), but it's the actual state.

## What works

- ✅ **Coverage is reasonable for prototyping.** 135 icons spans weapons / spells / consumables / armor / UI utility / faction-specific.
- ✅ **Attribution is automated** (`ATTRIBUTION.md` is generated by `freelib_ingest.py`; CC-BY tracked).
- ✅ **Atlas works.** 4096² atlas with 135 regions + JSON region map. Drop into Godot, you have a working `AtlasTexture` per icon.
- ✅ **Faction system has palette + per-faction 9-slice frames + per-faction HUD mockups.** That's a solid template.
- ✅ **Free-license fallback is real.** 103 cached SVGs in `freelib_svg_cache/` mean we can keep adding icons without API spend.

## What's open / weak

1. **Cloud routes never ran.** 6 PixelLab plans, 1 ComfyUI plan in `diffusion_plans/` are paper-only. **`prompts.json` has 6 prompts** for hero icons (`ico_dragon_head`, `ico_amulet_lunar`, `ico_spell_fireball`, etc.) that **don't have output PNGs.** Either the cloud lane was never triggered, or it failed silently. Worth checking.
2. **Procedural icons are visibly simple.** 1-3 KB / 256² PNG = flat-shape silhouette. Fine for prototype, **not a hero-quality icon**. If a real game ships, these get replaced.
3. **LoRA training never happened.** `lora/v1_smoke` and `lora/v3_smoke` have train commands + dataset scaffold but no checkpoint. The "train a faction-specific LoRA so synth_icons can render in-style" idea is unimplemented.
4. **Mixing sources may be visually inconsistent.** A first-party `ico_dagger.png` (1.3 KB simple line) sitting next to a game-icons.net `ico_gi_battered_axe.png` (15 KB detailed) at the same atlas slot will look weird side-by-side. **No style-unification pass has been done.**
5. **`preview.png`** is a 592 × 12248 vertical strip — composite of all icons stacked. Useful for seeing the whole library at once, but it's an artifact of an old run; nothing currently regenerates it.
6. **HUD mockups are tiny PNGs (16-19 KB).** That suggests they're built procedurally from icons + 9-slice frames with PIL, not painted compositions. Real "this is what the game looks like" mockups would be richer.

## User verdict (2026-05-07)

After eyeballing all three samples:

1. **Atlas (`ui/atlas/atlas.png`):** "ok, not amazing, but good placeholders."
2. **Faction HUDs (ashen_pact vs ember_legion):** "**just a color swap.**" Faction system at the visual layer is unproven — the system has palettes + per-faction frames but they don't add up to visually-distinct HUDs.
3. **Library overview (`ui/preview.png`):** "all ok, they would just need much better work but they are good starters."

**Net read:** the UI lane delivers usable placeholders; nothing on disk is final. The faction system is the weakest link — it's *plumbed* (palettes + per-faction 9-slice frames + named HUD outputs) but doesn't *produce visually different factions* yet. That's a real gap, not a quality nit.

## Pipeline-level read

- **State:** **working placeholder pipeline.** All outputs serviceable as prototypes, none final.
- **Strongest part:** the *infrastructure* (atlas builder, attribution tracker, free-license SVG ingestion, 9-slice slicer, Godot exporter). Plumbing works.
- **Weakest part:** **faction visual differentiation.** Mockups read as a color swap, confirmed by user inspection. The faction template exists but doesn't produce art that actually feels different per faction.
- **What "shipping quality" would require:** either (a) train the planned LoRA on per-faction art reference + run cloud routes (FLUX-schnell + PixelLab + Recraft) for hero icons + faction-specific HUD compositions, or (b) commission a stylistically-unified pack and replace the mixed-source library entirely.

## Concrete next moves (ranked, if you want to push UI further)

1. **Stop calling factions "differentiated."** They aren't yet. Either commit to actually making them visually distinct (next moves below) or document them as "color-only theming" honestly.
2. **Real per-faction HUD authoring** — beyond palette swap. Different frame ornament shapes, different icon choices per slot, different layout density. This is mostly an authoring/design task, not a tooling task.
3. **Train one faction LoRA** (`v1_smoke` has scaffold). ~30 min train. Confirms the LoRA loop works end-to-end and tests if "ashen_pact style" can actually be learned from a small ref set.
4. **Run the 6 prompted cloud icons.** `pipelines/ui/recraft_icons.py` against `prompts.json`. ~$0.50 spend. Confirms cloud lane and gives us 6 hero-quality references to compare against the procedural baseline.
5. **Stylistic unification pass.** Pick 1 visual style, batch through stylize ControlNet. Or commit to "intentional mixed style for prototype" and stop pretending otherwise.

## Research-calibrated update (2026-05-07)

Brief #07 ([response](../research_briefs/2026_05_07_sota_survey/07_ui_icons.response.md)) returned. **The brief validates our review — running the cloud lane + LoRA training is the unblocking step we already identified, with confirmed 2026 tooling.**

### Headlines

1. **Two version bumps unblock the existing cloud lane:**
   - `recraft_icons.py` → **Recraft V4 Pro Vector** (Feb 2026 rebuild, native SVG output, $0.30/SVG, ~$9 for 30 hero icons)
   - `local_diffusion_icons.py` FLUX-schnell → **FLUX.2 Klein 4B** (Apache 2.0, ~13 GB, **commercial-safe**, day-0 ComfyUI support on Blackwell)
2. **Faction LoRA scaffold is the single biggest unlock.** **AI-Toolkit by Ostris** is the 2026 community default trainer with documented Blackwell/PyTorch 2.9.1 path. 15-25 hand-curated images per faction, ~30-60 min train per faction on the 5090. **Apply at inference via rgthree's Power LoRA Loader** — one workflow, faction selector, hot-swap. **This is the answer to the "color swap" criticism.**
3. **There is NO 2026 AI tool that generates production game HUDs end-to-end.** Galileo / Uizard / v0.dev / NightCafe all produce static screenshots that don't respect 9-slice, don't reuse atlas, don't round-trip into Godot. **Viable answer: AI for the *materials* per faction (frame metal, banner cloth, parchment), then PIL-composite as today.** Keeps 16-19 KB HUDs but makes them feel genuinely different.
4. **Style-unification for the 135 mixed-source library:** ComfyUI graph (FLUX.2 Redux multi-reference + Canny ControlNet + img2img). Canny preserves silhouettes; Reference-only is largely deprecated for FLUX. No dedicated "icon-set unifier" exists in 2026.
5. **Free-license library expansion:** **Tabler Icons (6128+, MIT)** is the biggest *quantity* win for generic inventory glyphs. Plus **Iconoir (1600, MIT)** + **OpenGameArt 700+ RPG (CC0)**. **Don't ingest Flaticon "Fantasy RPG"** — non-CC0, forbids redistribution.

### What NOT to do

- **Don't pursue AI HUD generators.** Wrong tool category for game UI.
- **Don't replace vtracer/resvg/PIL atlas packer.** All laterals; current stack is correct.
- **Don't ingest Flaticon "Fantasy RPG"** — non-CC0/MIT, restrictive.
- **Don't replace procedural HUD compositor.** Keep PIL composites; layer AI textures on top per Q3 Route B.
